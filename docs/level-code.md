# Level-code encoding and decoding

EncodeLevelCode (5042..51A1, 352 bytes) and DecodeLevelCode
(51A2..52D3, 306 bytes) share the live DS template and selection state.
Their native cores live in c/main_menu.c and use the existing canonical bus,
register boundary and near-return handling. The original routines have no
children. This closes the transform pair, not the keyboard editor or code-entry
screen above it.

## State and format

The ten-byte template at DS:4913 is initially `AJHLDHBBCJ`. The encoder reads
selection 1F6B, payload 491D and completion display byte 0040, and writes ten
bytes at 4D68. Its first seven bytes OR template bits with interleaved selection,
low four payload bits and low seven completion bits. Template bits are not
cleared or validated. Bytes seven and eight add the selection's low and high
nibbles to the corresponding live template bytes, with byte wrap. Byte nine adds
the low nibble of the first nine generated bytes' wrapped sum to template byte
nine. The trailing CR at 4D72 is untouched.

The encoder then rotates the first seven bytes right `8 - (selection & 7)`
times. In particular, selection low bits zero cause eight rotations, rather
than zero or seven. The decoder validates the checksum before extracting the
selection from bytes seven/eight, writes that selection to 1F6B, and rotates
the first seven entered bytes left by the same count. It reconstructs a second
selection from those seven bytes and requires equality. Success writes unsigned
selection / 30 to group 1F6E, including groups above three, and the decoded low
four payload bits to 491D. Completion is encoded but is not decoded into 0040.

The separate input buffer is DS:4DF2. Every access remains on live DS; there
is no host string, template clone or converted game record in the C routines.
The decoder's actual PUSH SI / POP SI is retained. A stack alias can change
input or template bytes, and a changed saved SI changes subsequent source reads.
The bytewise rotations reread sources after each preceding store. DIV leaves
its architecturally undefined flag values as pinned-executor observations;
the successful decoder exit subsequently defines the consumed ZF with SUB.

## Failure and return contracts

Five word comparisons first recognize exactly `BILLANDTED`. A match writes FF
to latch 1F74 before checksum validation. Other inputs do not clear the latch.
With the pinned template, that special input still fails the checksum; the latch
write survives. Its consumer at 024D remains a separate frontier.

A checksum mismatch returns ZF clear without rotating the input or writing the
selection. Stack alias effects from the preceding PUSH SI are still observable.
A later duplicate-selection mismatch retains the new selection and the in-place
rotation; it does not roll them back. Group and payload updates occur only after
both checks pass. Success ends with SUB AH,AH, setting ZF and leaving AH zero.
The C status describes the declared boundary, not code validity: callers must
consume ZF as the original 499C branch does.

Both cores stop before their original RET (51A1 / 52D3). Adapters read the actual
caller word from live SS:SP and advance SP with 16-bit wrap. BX, BP, CS, DS, ES
and SS remain live; DF is retained, and the routines do not use string instructions.
All intermediate register values, defined flags and ordered canonical accesses
are compared against bounded original instruction execution.

canonical access, guarded callbacks and state comparison. No new CPU or comparison
engine is introduced. The transform cases cover all 256 selection values, three
load segments, high payload/completion bits, altered live templates, DF, distinct
DS, physical addressing near the A20 boundary, stack wrapping, input/template
stack aliases, changed saved SI, every special-word comparison and both failure
stages. Independent bit-layout expectations supplement the original/C comparison.

Three same-memory sequences encode and then decode submitted output. The ten-byte
submission is an explicitly constructed external input boundary. It does not stand
in for acceptance of ReadCodeInput or the 4967 screen. Game/device state remains
live across the compared stages.

Mutation witnesses distinguish rotation count, OR versus XOR on nonstandard live
templates, checksum masking, special-latch timing, early selection writes, input
rotation, unsigned group division, payload width, unwanted latch clearing and
restoring a fixed SI instead of the actual saved word. A completed mismatch is
required for credit. Native calls use the existing bounded worker and owned build
directories; time, memory and access exhaustion never count as mutation evidence.

The first changed-SI fixture patched a byte after its read had already been
observed, and failed the shared canonical-memory consistency check. The corrected
finite provider publishes the changed word before that read; no game C or shared
oracle behavior was changed to hide the failed fixture. An initial corruption
witness flipped a completion bit and was accepted by the original, so it was
replaced with a selection-bit corruption at its actual rotated position.

The keyboard editor's indirect transfers at 4CC9 and 4D18, the 503B text bridge,
the 4967 screen and level/game startup remain separate work. UNKNOWN byte and
transfer accounting is unchanged by naming these already decoded transforms.

## Static handoff to the remaining editor

The existing indirect evidence already records 503B as the known target of
CALL BP at 4CC9 and JMP BP at 4D18. Entry 4C88 supplies BP, and each display,
text and keyboard cycle restores actual saved BP words. That is a conditional
target contract; arbitrary stack/segment aliases are still open. No additional
indirect target or whole-program closure is inferred from the codec tests.

Entry 4C95 initializes byte 491E to 20. Each wait cycle decrements it; zero
reloads 20 and toggles the current input byte between saved CL and underscore
CH. The known 503B callback draws the stream starting at 4DEF. The inner cycle
saves DI, SI, CX, DX and BP across wait and drawing; the outer edit cycle also
saves BX. Those are live stack words, rather than a host editor model.

The input range is ASCII A..Z, with signed comparisons. FF means no key, 7F is
backspace, and CR submits. On the tenth accepted letter the cursor is moved back
to the final slot, so later letters can replace that slot. Backspace first writes
a dot at the current cursor, then moves left and remembers the preceding byte;
it does not immediately erase that preceding byte. Submission clears the whole
1FC7 word, restores the cursor's saved CL byte, and tail-JMPs through live BP.
These details must be checked while composing the native editor and text bridge.
The memory DEC at 4CAD exposes its incoming flags on the write callback, then
its result flags control JNZ; the native editor must retain that ordering.

The valid-code screen also calls 488C to format a one-based level and rating.
That helper saves actual CX, increments the selection as a byte before dividing
by 30, and rereads the live selection after MUL. A zero remainder becomes level
30 while AH is decremented. Selection FF therefore produces AX=FF1E under the
ordinary stable-memory contract, rather than a normalized level/group pair.
Its stack and second read must survive translation; replacing it with a single
host division of a widened selection would change the original wrap behavior.
