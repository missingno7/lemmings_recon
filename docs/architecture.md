# Architecture and reference adaptation

The project follows Pre2's exact ASM oracle -> portable C11 -> bounded Unicorn
comparison -> native host sequence. The following reference files were inspected:
README, AGENTS, executable/architecture/completeness/translation-brief docs,
src/MODULE1.ASM, c/sqz.c, tests/sqz.py, host/main.c, and tools verify/build/cbuild,
explore/graph/where/define/rename/difftest. No neighboring repository is modified.

Reusable ideas: fail-closed hashes; byte identity independent of semantic names;
recursive descent seeded with evidence; unknown-byte markers; canonical memory
with generated symbols; explicit contracts; bounded original routine execution;
poison and mutation tests; separate translation and execution coverage.

Adaptations: this executable is PKLITE-packed, so static decompression and independent
relocation checks precede reconstruction. NASM emits a flat canonical image; no DOS
TASM/TLINK emulator is needed. Assembly is maintained in src and never regenerated by
verification. tools/reconstruct.py is an explicit bootstrap/reclassification command:
it can overwrite comments and must not be used casually once source is hand-refined.
It writes unknown bytes explicitly, not through INCBIN. NASM opcode alternatives
are individually roundtripped and documented in encoding-exceptions.json.

Ownership: src is the executable specification; metadata/symbols.json owns names,
confidence and offsets; metadata/hints.json owns manually evidenced discovery/class
facts. metadata/regions.json is the reproducible complete byte partition, including
unresolved spans and overlapping uses. Derived listings/graphs/reports live in build.
Every original asset is private. No legacy lifted implementation is imported.

The maintained ASM now has physical modules with separate resource, special-strip
and checksum ownership. Broad game/tail ownership remains provisional. Routine
contracts live beside the ASM and named data coordinates stay ledger-owned.
The fresh graph's call tree and pending dependency order guide the next C cluster;
see [bottom-up convergence](bottom-up.md) for the source layout, record handoff,
open native seams and working loop adapted from Pre2.

c owns translated logic on a canonical DOS backing memory. The C11 headless
[host](../host/README.md) now binds VGA, virtual PIT/PIC timing, keyboard/mouse,
read-only DOS files and BIOS services beneath the verified loop. It constructs a
declared post-startup handoff and runs the maintained MAIN.DAT producers; full
startup and sound engines remain unsupported. The release runner loads the pinned
EXE with the native PKLITE decoder and has no Python/Unicorn/SDL dependency.
Only tests and bounded original verification use Unicorn; build tools use Python.

External source references were reviewed as concept references only:
[LemmixPlayer](https://github.com/AaronKelley/LemmixPlayer),
[Lemmix](https://github.com/ericlangedijk/Lemmix),
[Eric-Lautanen/lemmings](https://github.com/Eric-Lautanen/lemmings),
[VorticonCmdr/lemmings](https://github.com/VorticonCmdr/lemmings).
No gameplay logic or semantic name has been copied from them. Naming must continue
to be supported by the original instructions. PKLITE research references include
[Jason Summers' analysis](https://github.com/jsummers/pkla); the implemented decoder
was derived directly from this binary's stub, not downloaded code.

Current C interfaces mix semantic leaf inputs with register-role packets. For example,
the entity interaction core takes live segments, record/object cursors, stack,
count, auxiliary value and flags; it returns observed results and a continuation.
Its entry overwrites AX/BX, while BP/ES are preserved by the body and composed
pinned sound prefixes, so those four registers are not inputs to that core.
The oracle adapter reconstructs full machine state and performs the actual RET.
Machine-register packets used by the INT60 connector describe its declared CPU
boundary. They are transient values at that boundary, with canonical RAM still
the only game-state owner. Entity-update and renderer packets still carry nearly
complete machine state despite their role names. These are retained verification
boundaries, not evidence that native game logic must expose every register forever.
Reduce one only after proving its caller/lifetime contract and preserving the
original adapter evidence; do not rewrite functioning C just for appearance.

Translation readiness and the freeze bar are in [semantic-audit.md](semantic-audit.md).
Current status is [completeness.md](completeness.md),
derived by the existing coverage tool's fast `--inventory` mode. It separates
implementation ranges from matching differential evidence and whole-game closure.

## Portable C and complete-game convergence

The maintained path is original executable -> exact semantic ASM -> portable C11
over canonical original memory -> native platform services -> SDL3 application.
An intermediate runnable 16-bit DOS-C hybrid is not required. It would add a
second compiler ABI, far/near bridges and segment placement constraints without
removing the native platform work. Overkill used that path to retain its original
DOS hardware backend; see its [DOS hybrid design](https://github.com/missingno7/overkill_recon/blob/main/docs/dos-hybrid.md)
and [native host design](https://github.com/missingno7/overkill_recon/blob/main/docs/host-port.md). Lemmings
already has portable native C and bounded original/native comparisons.

The permanent specification is the pinned ASM, ledger and proven data contracts.
C keeps the original records, offset identities, wrap, signed predicates, shared
tails, bugs and behavior-affecting memory. Returned DS/ES/SS, actual stack words,
flags and code modifications remain explicit wherever the original consumes them.
One memory image owns game state; no converted record copies are synchronized.
Pre2's particular segment/stack contract is not imported. Shared C helpers express proven
operations rather than interpret instructions or hide an unresolved transfer.

Native C-to-C composition uses the same tested cores. Offset dispatch selects
identified C functions and preserves actual frames where observable. Unknown
targets stop explicitly. Test adapters are boundaries, not a second game engine.
The final game executes C exclusively: no original instruction fallback, legacy
interpreter, or CPU emulator at runtime. The test oracle may execute identified
original routines with constructed state under the existing bounded policy.

Every behavior-affecting executable region, including executable sound modules,
must have an explained C implementation. Being an alternative hardware path,
error path or currently unexecuted region does not by itself close that obligation.
Tables, assets, initial bytes and checksum operands remain explained data with
proven consumers and formats; their bytes need not become C algorithms. UNKNOWN
bytes and incomplete target domains remain explicit until evidence closes them.

Platform services model BIOS/DOS interaction, VGA, input, PIT/PIC and sound behind
declared contracts. SDL3 presents those services after the C core is connected.
Translation alone does not supply interrupt scheduling, clock progression, device
initialization or audio/video presentation: these are required integration work.
Exact behavior is assessed against the pinned executable and a stated machine
configuration, clock/input schedule and service contract.

The integration milestones are connected input, timer/game-state coordination,
complete startup/resource/level/frame composition, remaining executable drivers,
then the native platform and SDL3 host. Prioritize dependencies that unblock the
next composed caller instead of accumulating unrelated isolated leaf ports.

Final acceptance includes a deterministic native startup-to-gameplay smoke run,
scripted input, bounded virtual time, state/frame/audio checkpoints, and exit.
Follow with level/session transitions and longer bounded gameplay. Compare
checkpoints with bounded original-region evidence and independently checked
device behavior. A successful smoke run is necessary integration evidence, not
proof that every state or hardware timing case matches. Byte classification,
translated code, executed sites, connected C domains and native behavior remain
separate measurements. Never boot the original game for discovery.
